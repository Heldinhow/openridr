# Glossário

- **Solution Explorer**: árvore da solução aberta (projetos, dependências, arquivos). Mostra o modelo avaliado pelo MSBuild quando existe; senão, um outline de texto.
- **Tool window**: painel acoplado a uma faixa lateral ou inferior (Build, Problems, Debug, Terminal, Tests…). Cada slot mostra uma por vez.
- **Run configuration**: configuração nomeada de execução (projeto, argumentos, ambiente) escolhida na barra superior; serve para Run e Debug.
- **Startup project**: projeto console que Run e Debug executam; implícito quando há um só.
- **Launch profile**: o perfil de `Properties/launchSettings.json` importado para o projeto e escolhido no seletor da barra; é read-only no app e define ambiente, argumentos, `applicationUrl` e o que fazer com o navegador. _Avoid_: run configuration (é a configuração nomeada do app, não o perfil do arquivo).
- **Launch browser**: a abertura da URL do launch profile no navegador padrão depois do início do Run ou do Debug, quando o perfil pede (`launchBrowser`) e o endereço começa a aceitar conexão. Não é "abrir o navegador do app": o OpenRidr não tem navegador embutido.
- **Build implícito**: o `build.start` que o host inicia sozinho quando Run ou Debug não têm um build atual utilizável (ausente, stale, falho, TargetPath/assembly sumido, fonte salva alterada). A aba do lançamento mostra `building`; só o exit 0 observado libera o processo. Não restaura: `restore_required` continua sendo uma ação explícita do usuário.
- **Automação que constrói**: o trabalho que o próprio app inicia e que roda MSBuild — a descoberta automática de testes (que constrói o projeto de teste e as referências) e a análise enquanto carrega a solução. Não é o build do usuário e não é o restore: é o que o host precisa serializar contra o build explícito. _Avoid_: build automático (confunde com o Build implícito, que é um build de verdade do usuário).
- **Debug preparation**: o que o clique em Debug na barra faz antes de lançar quando falta o adaptador — confirmar a flag experimental e planejar/instalar o netcoredbg. Não faz mais restore, avaliação nem build: o host constrói implicitamente quando o build não serve.
- **Recent project**: solução ou projeto aberto antes e listado na tela inicial, com nome, caminho e último acesso. Remover da lista não altera sua Trust decision.
- **Trust decision**: escolha do usuário, uma vez por projeto, entre confiar (*trusted*) e abrir em modo restrito (*restricted*). Persiste entre sessões e pode ser mudada depois.
- **Trust prompt**: a pergunta única que oferece a Trust decision na primeira abertura de um projeto. Não reaparece depois de decidida.
- **Restricted mode**: abertura sem executar código do projeto (sem build, run, debug, análise); só edição de texto.
- **Stop source**: qualquer motivo configurado para o depurador pausar o programa em execução — um breakpoint (quando não mutado), a parada em exceções lançadas, o pause manual ou o run-to-cursor. Sem stop source, a sessão roda até o fim sem parar.
- **No-stop session**: sessão de debug que terminou sem nunca ter pausado. O fim dela precisa ser explicado, porque não há threads, frames nem locals para mostrar.

- **Working-tree diff**: o diff que o painel Git mostra de um arquivo alterado da árvore de trabalho; a base é o index (arquivo sem stage) ou o `HEAD` (arquivo todo em stage). Nunca é um diff de commit.
- **Diff base**: o lado esquerdo do diff — a versão contra a qual o lado atual é comparado. A do working-tree diff é o index ou o `HEAD`, nunca os dois.
- **Diff mode**: a forma de mostrar o working-tree diff: *split* (dois editores lado a lado) ou *unified* (um editor só, com prefixos `-`/`+`). A escolha é do painel, não do arquivo.
- **HEAD commit**: o commit para onde o `HEAD` aponta; é o hash mostrado no diff como contexto da comparação. Não confundir com o blob hash do index, que identifica conteúdo e não revisão.
- **Commit diff**: o diff de um arquivo de um commit, aberto pela lista de arquivos do Git log; a base é o primeiro pai do commit (nada, num commit raiz) e o lado atual é o próprio commit. Os dois lados são blobs, então o diff não muda com o que está na árvore de trabalho. _Avoid_: chamar de working-tree diff.
- **Conditional breakpoint**: breakpoint que só para quando uma expressão C# do projeto é verdadeira no momento do hit.
- **Hit count**: número de paradas no mesmo breakpoint antes de o debugger parar; conta só os hits aprovados pela condição. _Avoid_: hitCondition (nome do DAP no adaptador).
- **Watch**: expressão C# fixada pelo usuário no painel Debug e reavaliada a cada pausa contra a thread/frame selecionados.
- **Local test remote**: a bare repository under the temporary directory plus two throwaway clones — the one the app opens (`user`) and the counterpart (`peer`) — used to exercise real Git operations with no network and no credentials. Never a project of the maintainer and never an external remote.
- **Counterpart (peer)**: the second clone of the local test remote that publishes commits and branches the workspace is expected to receive. Driven outside the app so the effect is real, not simulated.
- **Fetch**: a ação de Git que traz as refs do remoto para a cópia local (`git fetch --prune`), sem tocar na branch, no index nem na árvore de trabalho; é a única coisa que deixa o **Behind count** e a lista de branches remotas em dia, e é sempre explícita — nada no app busca sozinho. _Avoid_: refresh (é a leitura local do status), sync, update (Update traz o upstream para a branch local).
- **Behind count**: the distance between `HEAD` and the local tracking ref, shown as `↓N`. It is only as fresh as the last fetch or push; an `Update…` (pull) fetches and may incorporate work while the count still reads zero.
- **Divergent branch**: a branch whose local commits and upstream commits both moved, so a plain pull cannot fast-forward. `Update` reconciles it with a merge commit; local commits are never rewritten.
- **Update**: a ação de Git que traz o upstream para a branch local (um `git pull`), com a política que o diálogo declara: merge quando os dois lados andaram, nunca rebase, e, quando o merge conflita, ele fica em andamento para ser concluído ou abortado pelo menu de branches. _Avoid_: pull (é o comando e a configuração dele), sync, refresh.
- **Cancel (Git network)**: a ação que interrompe um **Fetch**, um **Update** ou um **Push** que está esperando o remoto, devolvendo o controle na hora em vez de esperar o prazo. O que a operação já recebeu do remoto fica, e o app diz o que ela pode ou não ter mudado: um push cancelado pode ter chegado ao remoto, um Update cancelado nunca deixou merge pela metade. Não cancela o passo local do Update (o merge) nem Build/Run/Debug. _Avoid_: abort (é o do merge em andamento), stop (é o do Build/Run/Debug).
- **Merge in progress**: o estado em que `MERGE_HEAD` existe: um merge foi começado e seu commit ainda não foi criado, então a branch, o index e a árvore estão no meio do merge. O OpenRidr conclui (stage dos caminhos conflitados e commit com a mensagem preparada) ou aborta pelo menu de branches. _Avoid_: conflicted tree (é o sintoma, não o estado), merge pendente.
- **Risk tier**: o quanto um pull request pode quebrar o produto, classificado pelos caminhos que ele toca — baixo (documentação, testes, estilo), médio (código de produto) ou alto (CI, release, assinatura, modelo de trust, atualização e dependências). Um PR misto recebe o tier mais alto entre os caminhos que toca. Decide se o PR precisa do mantenedor ou pode ser mergeado sozinho.
- **Risk label**: o rótulo `risk:low`, `risk:medium` ou `risk:high` que anuncia o Risk tier de um PR. É sempre saída do cálculo, nunca entrada: editar o rótulo não muda o tier nem libera merge.
- **Maintainer approval**: review aprovado por quem mantém o repositório numa revisão do PR posterior ao último commit dele. É o que libera o merge de um PR de risco alto; aprovação de uma revisão antiga não conta.
- **Auto-merge**: fusão em squash que o GitHub executa sozinho quando os checks obrigatórios ficam verdes, armada apenas para PR de risco baixo.
- **Revert rate**: proporção de PRs mergeados que precisaram ser revertidos, contada por mês, usada para saber se o gate de risco está calibrado.
- **System proxy**: o proxy configurado em Ajustes do Sistema → Rede → Proxies do macOS, lido por `scutil --proxy` sem elevação; é a fonte que vale quando o ambiente não nomeia proxy nenhum. _Avoid_: proxy do app (não existe campo de configuração no OpenRidr), PAC (é outra forma de configuração, não suportada).
- **E2E app home**: o `OPENRIDR_HOME` isolado que o harness de E2E dá ao host — nunca o app home real do usuário. O default é derivado da porta da UI (`openridr-e2e-home-<porta>`), então duas execuções com portas diferentes não compartilham ferramentas, trust nem recentes; `OPENRIDR_E2E_HOME` vence. _Avoid_: chamar de app home (é o do usuário, em `~/Library/Application Support/OpenRidr`).
- **E2E screenshots dir**: o diretório onde os specs gravam as capturas de evidência. O default é derivado da porta da UI (`openridr-e2e-screenshots-<porta>`) no diretório temporário, nunca dentro do repositório; `OPENRIDR_SCREENSHOT_DIR` vence e é o único caminho para escrever em `docs/evidence/screenshots`. _Avoid_: chamar de evidência versionada (é o diretório do repositório, que só recebe captura quando pedida).
- **Porta restrita**: porta que o navegador recusa por política (`ERR_UNSAFE_PORT`) mesmo com um servidor escutando nela — a lista é a do próprio Chromium, e o Playwright usa Chrome por default. Nem a porta da UI, nem a do host, nem as derivadas dos specs (a faixa que o host reserva para os specs que sobem host próprio) podem cair nela. _Avoid_: porta inválida (é a que não é inteiro de 1 a 65535), porta ocupada (é a que outro processo já escuta).
- **Download stall**: a janela de silêncio que o download de ferramenta tolera antes de falhar — 60 s sem um único byte. É o que substitui o prazo total: enquanto bytes chegam, a transferência continua, por mais lenta que seja. _Avoid_: timeout (é o nome da API; o conceito é a inatividade), deadline.
- **Update channel**: a release de tag fixa (`updater-alpha`) cujos assets são substituídos a cada versão e de onde o app instalado lê o manifesto. Não é a "última release": toda release do projeto é pré-release, e `releases/latest` só aponta para a última não-pré-release. _Avoid_: latest release.
- **Update manifest**: o `latest.json` que o app checa — versão, notas, data e, por plataforma, a URL do artefato e a assinatura dele. O manifesto em si não é assinado; o que prova a origem é a assinatura do artefato mais a versão gravada nela.
- **Update artifact**: o `OpenRidr.app.tar.gz` e o `.sig` que o updater baixa e instala — empacotado do `.app` já notarizado e grampeado, com `OpenRidr.app/` como raiz única e **sem** entrada AppleDouble (`._`), que o leitor tar do plugin não sabe desempacotar. _Avoid_: chamar de DMG (o DMG é o caminho manual, e o update não o usa).
- **Job informativo**: job de CI que roda e reporta em todo PR mas não pode deixar o check obrigatório vermelho — hoje, `continue-on-error: true` no job, que faz o `result` dele virar `success` para o agregador `ci`. Informativo é sobre **poder bloquear**, não sobre rodar: o job executa igual, e a promoção é remover a flag, nunca mexer no ruleset. _Avoid_: job opcional (não existe job opcional no GitHub), job desabilitado.
- **Auditoria de dependências**: a conferência dos lockfiles (`bun.lock` e os dois `Cargo.lock`) contra bases de advisory conhecidas, semanal e fora do caminho do PR. Não é Dependabot (que propõe bump) nem gitleaks (que procura segredo): o que ela responde é "esta versão tem vulnerabilidade publicada". Falha do scanner é vermelho — "não rodou" nunca é "não tem". _Avoid_: audit (é o nome do comando), Dependabot, scan de segredo.
- **Dependência não listada**: pacote importado direto pelo código da UI e ausente do `package.json` da raiz. Hoje resolve porque chega por transitividade, então o bump de um terceiro pode removê-lo e quebrar o build sem nenhum PR deste repositório tocar no assunto. _Avoid_: dependência fantasma, dependência implícita.
- **Poll do disco**: a re-leitura periódica (1,5 s) do arquivo ativo que o editor faz para notar mudança externa; buffer limpo adota o texto do disco, buffer sujo ganha um **Conflito de disco** e nunca é sobrescrito. Não roda com a janela oculta — aí quem cobre é o evento de foco. _Avoid_: watch (é o do sistema de arquivos, que o app não usa), refresh.
- **Conflito de disco**: o estado em que o texto do buffer difere do que está em disco e o app se recusa a salvar até o usuário escolher Reload from disk ou Overwrite disk. O overwrite revalida contra o hash que o usuário viu, então uma segunda mudança em disco gera um conflito novo em vez de ser sobrescrita em silêncio. _Avoid_: conflito de merge (é o do Git, outro estado).
- **Check proporcional**: o check que o hook de pre-commit roda num commit, decidido pelos caminhos daquele commit — nada quando só documentação mudou, `tsc` quando o commit não tem Rust, `cargo check` quando só tem Rust, os dois no misto. _Avoid_: check completo (é o `bun run check`, que continua sendo o comando manual e o do CI).
